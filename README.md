# SplitChunkAssistant

> **RAG 切块的可视化人工切片工作台** —— 自动切完能看、能改、能存、能导出。

给本地 FAC-RAG（默认 `C:\Users\QiuYe\Desktop\FAC-RAG`）的 `chunking_v2` 切块流水线挂一个本地网页工作台：
原文（Markdown）与切片（chunk）双向联动，支持人工 `split / merge / drop / add / 改字`，
支持调整切分参数后重切，人工修改写入覆盖层，导出仍然是原来的 **15 字段契约**。

**当前状态：P2 已实现（2026-11-03）** —— P1 的「原文 ↔ 切片」三栏只读联动之上，已支持人工编辑：

- 每个切片的卡片底部有 **拆 / 并↑ / 并↓ / 删 / 改** 五个操作（首尾块的「并」自动禁用）；
- 在原文拖选覆盖 2 个以上切片后右键，菜单里会出现「**⤵ 合并所选 N 个切片**」，一次把选中的连续多块合并成一块（保留第一块 id/条号/kind，行区间取并集；散块不允许，避免误吞）；
- **在原文里拖选一段文字 → 右键**：弹出上下文工作栏，可直接「用选区新增切片 / 拆分此切片 / **✎ 编辑此切片正文·条号** / 并入上一块 / 并入下一块 / 删除此切片 / 定位到切片」，
  执行后右栏切片列表与原文范围条**立即刷新**（无需刷新页面）；
- **右键落在标题/目录/空行等没有切片的原文行**：菜单不再消失，而是显示「ℹ 第 N 行不属于任何切片」，并给出「**✚ 用这一行新增切片**」——把这一行原文带入新增弹层（可改正文、条号、kind）；顶部缺口新增的块会**插到列表最前面**，保持原文顺序；
- **在原文里拖选一段文字，点「＋新增」即可把选区变成新切片**：正文自动带入、行区间一并记录
  （新块带「手工」徽章、`span` 行区间，原文范围条上能看到它，也能点击联动定位）；不选区时仍可手动输入正文新增；
- 顶部工具栏：**未保存徽章**、**diff 计数 `+新增 ~修改 -删除`**、**撤销 / 重做**、切片面板 **新增 / 重置**；
- 拆分支持 **行级（多行块给行单选）**、**字符级（单行块给字符位置）**、**在原文光标/选区处直接拆**（右键工作栏首项「✂ 在此处拆分 / ✂ 在光标处拆分」，按落点在块内第几行自动选行级或字符级）；合并必须相邻、**「并↑」「并↓」两个方向都支持**、保留前块 id；
- **拆开的两块会自动补回原文行区间**（不再显示「未对齐」）：右栏卡片各自显示新的行号范围、左侧范围条立即断成两段；拆分弹层可填「**下半块条号**」（留空时自动识别切点处的条号——「第X条」或「5.4.1」这种标准式层级号，识别不到才继承原块——合并多块再拆开时，下半块会拿回自己的条号），之后再想改条号用卡片「改」或右键「✎ 编辑此切片正文·条号」即可；
- **新增块的条号按前后邻居倒推**：不填 `law_num` 时，优先沿用前一块的条号（「第X条」或「5.4.1」这种标准式，判断为同一块的续写），前面没有就看后一块；新增弹层会实时提示「留空则按前后块倒推：第二条 / 5.4.4」；表号 / 附录号 /「（新增）」不作为倒推参照；
- **合并块显示覆盖条号**：合并多块后，卡片头会出现「**覆盖 第一条–第三条（3 条）**」或「覆盖 5.4.1–5.4.4（4 条）」徽章（从块的行区间 + 原文里的条号倒推，纯 UI 提示，不写入 15 字段契约）；
- **拆分光标反馈**：在原文里点一下就会出现**蓝色拆分光标 + 上方提示气泡**——告诉你落在第几行、会按「行边界」还是「光标处」拆分、拆的是哪个切片；不可拆的位置（块首/块尾/折叠行）会直接提示原因，不属于任何切片的行也会说明；同时右侧对应卡片蓝色描边高亮。点行号列不会误触光标。
- **表格可视化（P2 已实现）**：原文里连续的管道表（`| … |` + `---` 分隔行）和 HTML 表（`<table>…</table>`，含整行 23 万字符的超长表）会在行内渲染成真正的表格，表格外层有「管道表 / HTML 表 · 第 a–b 行」的说明，块内行隐藏但行号/范围条仍按区间显示；右侧表切片卡片按 `extras.table_grid` 画成同一套网格表（表头、合并单元格抄平、注释行黄底），并把「送进检索的原始正文」折叠在下方 `<details>` 里；手改过正文的表格块不再用旧网格（避免显示过期内容）。表格数据按文件懒加载（`/api/tables`，山东自由裁量标准 684 张表约 400KB，不塞进 `/api/doc`）；单击表格卡片会把原文表格整块高亮/滚到可视区；拖选表格内文字也算选中该表格块；表格块左侧的范围条按整块高度竖向铺满（不是只留一条缝），所以表格行区间的归属一眼可见。**整张表只占源码一行**时（如山东第 588 行 23 万字符的 HTML 表，被切成 679 个表格块、span 全是 `[588,588]`），同一行叠加的切片数超过 4 条泳道后，左侧合并成 **1 根彩色条纹聚合条**，tooltip 与表格 meta 里写明「679 个切片（源文件里整张表只占一行）」，点击聚合条选中第一个表格切片；普通表格块（1 个切片）仍按普通范围条显示。
- **编辑后保持表格预览的滚动位置（P2 已实现）**：删除/拆分/合并/改字/撤销等操作会重渲染原文，工具现在会记住**表格块内部滚动容器**和**右栏卡片内部表格**的滚动位置，重渲染后按「表格块起始行 / 卡片 id」恢复，并靠 `overflow-anchor: none` 关掉浏览器的自动滚动锚定，避免几像素漂移。删除切片后停在原行不动（状态栏提示「原文与表格位置保持不变」，Ctrl+Z 可撤销），不会再跳到表格顶部。实测：山东自由裁量表表格滚到中段 3600px → 删除第 700 行切片 → 表格容器、原文栏、右栏都保持原位（±0px），撤销后同样保持。
- **表格行按「看到的行」定位（P2 已实现）**：表格块里右键/左键某一视觉行时，工具按**鼠标坐标**找出该行的 `<tr>`，再读它记录的切片下标，所以菜单里的「✎ 编辑此切片」「✕ 删除此切片」以及点击选中的都是**这一行自己的切片**（此前右键总是命中列表第一个表格切片，因为整张表在源文件里只占一行、`chunkAtLine` 只能取到最靠前的块）。带 `rowspan` 的表格也不会错位——跨行单元格属于上一行的 `<tr>`，但坐标落在哪一行的行带里就取哪一行（实测右击第 120 行 → 目标是 `…-0239`，删除后第一行 `-0138` 仍在；第 300 行 → `…-0373`）。表格行不显示「在光标处拆分」；普通原文行仍按行区间定位。
- **表格内部按切片着色（P2 已实现）**：渲染出来的表格会把**每个表格切片覆盖的行区间**涂成该切片自己的颜色（行底色 + 首列 3px 色条，颜色由切片序号按黄金角旋转生成，山东自由裁量表 949 行有 360 种色相）；鼠标悬停表格行只联动**对应那一张**卡片（不会把整块的 679 张卡片全点亮）；**点击表格行直接选中对应切片**；反过来点卡片时，它的表格行会加深高亮并在表格容器内自动滚到可见。GB 50016 这类 `law_num` 带「表X 第a-b行」的 135 行同样着色；只有表号/附录号、没有行区间的表格块不着色（不假着色）。
- **拆分无反应时先硬刷新一次（Ctrl+F5）**：浏览器标签页可能还缓存着旧版 `app.js`；静态资源的 URL 已带 `?v=` 版本串，正常刷新即可拿到新代码；
- **在表格里新建切片（P2 已实现）**：①拖选表格里的文字 → 右键 →「✚ 用选区新增切片」（带入表格原文、记录行区间）；②不选中文字，直接在表格上右键 →「✚ 在表格块处新增切片」（带入整个表格块的源文本）。两种情况提交后右栏立即出现新卡片、范围条/表格着色同步。**新建的切片会自动选中并高亮**——右栏新卡片蓝框、原文那几行（表格块整块描边 + 左侧范围条色条）同步高亮并滚到可见，状态栏显示「已选中 … · manual · 原文第 a–b 行」；撤销后高亮自动清掉。此前「表格里右键新增没反应」的根因是右栏为选区联动自动滚动时把刚弹出的菜单关掉了，现已改为程序化滚动不关闭右键菜单（真实 Edge 回归：菜单 900ms 后仍在、两条新增路径都实测 83→84 卡、diff `+1 ~0 -0`、撤销回 83）；
- **表格未切片行可选中（P2 已实现）**：渲染出来的表格里没有被任何切片覆盖的行用**灰色斜纹底 + 首列虚线**标出来（山东自由裁量表 952 行里有 3 行缺口）；**单击**这一行会把它标成琥珀色选区并提示「表格内第 N 行 · 未切片」，**拖选多行**同样只标这些行（不再误选成 679 张卡片），**右键**弹出专用菜单：「ℹ 表格内第 N 行 没有切片覆盖」+「✚ 用这一行新增切片 / ✚ 用选中的表格行新增切片」，弹层带入这些行的单元格文本（`\t` 分隔列、`\n` 分隔行），提交后新切片自动选中并高亮。新增块的**插入位置按表格行顺序**决定：插在选中行上方最近的已切行之后（如第 215 行 → 第214行切片与第216行切片之间）；上方没有已切行时插到该表格第一个切片之前（如第 1 行）。因此删除一行切块再重建时，新块会回到原行位置，**不再被追加到表格块末尾**。已知边界：P2 契约只有块级行区间，所以从表格缺口新增的切片行区间记在**整个表格块**（原文第 588–588 行），行级缺口标记不会因为新增了整块切片而消失；要精确到行需 P5 的 `src_lines` 行级 provenance；
- **表格来源新增默认类型 + 手工表格网格视图（P2 已实现）**：从表格行 / 表格块新增时，`chunk_kind` 默认 `table`（普通原文选区仍是 `paragraph`，弹层里可改）；右栏对手工 `table` 块按正文里的 `\t`（列）/`\n`（行）还原出网格表，**表头从同一表格块已有切片的 `table_grid.headers` 继承**（列数匹配才用），表上方标注「手工表格 · 表头继承自该表格」，避免把表头写进正文——「原始正文（送进检索的就是这段文字）」仍折叠在下方，15 字段契约不变（纯视图层推导）。实测：山东第 215 行缺口新增 → 类型默认 `table`、条号仍预填、7 列表头继承、1 行 × 7 列数据、自动选中；GB 14444 表格块新增同样默认 `table` 且有表格视图；工具栏无选区新增仍默认 `paragraph`；
- **删除后重建 / 自动选中（P2 已实现）**：新建切片后，工具用「提交前后的块签名差」找出刚新增的那一块并自动选中/高亮，**不依赖 diff 的 `added_ids`**——所以像「删除某行切块 → 在同一行重建」这种内容与基线里被删块高度相似的情况，也能正确选中。此场景下 `diff` 仍按「与基线比较」显示成 `+0 ~1 -0`（新增块占了基线里被删块的逻辑槽位），属基线 diff 的已知语义，不影响新增块定位；
- **从表格新建切片时自动预填 `law_num`（P2 已实现）**：表格切片的条号形如「第二部分 裁量细则 表1 第214-214行」。选定表格行（或整个表格块）后打开「新增切片」弹层时，工具会用**上下相邻的已切表格切片交叉验证**推算这一行应有的条号：①分别找上下最近的两个已切行，取它们的「表号前缀 + 行区间」；②校验两行在表格里的偏移（`tbodyIndex - 表内行号`）一致、表号前缀一致；③推算结果必须严格落在两个邻居的行号之间，否则视为低置信、不预填；④选中行本身已被覆盖时直接用它的行号；只有表号没有行区间的块（如「附 录 C 表1」）只预填表号前缀。算出的值**写进弹层输入框**并在提示里注明「条号已预填『…』（按相邻切片推算，请确认），可修改」，不会静默落库。实测：山东自由裁量表唯一缺口第 215 行 → 预填「第二部分 裁量细则 表1 第215-215行」；GB 14444 整块新增 → 预填「附 录 C 表1」；
- **表格多行选择（P2 已实现）**：表格块里的整行选择不再依赖浏览器文字选区，而是自己维护行带选区——按下左键拖过哪几行就选中哪几行（行高 285–440px 也能准确取行；拖到表格容器上下边缘会自动滚动继续选），选区是琥珀色行底 + 首列橙条，状态栏实时显示「表格内第 a–b 行 · 已选 N 行（都有切片 / M 行有切片）· 右键可合并 / 删除」；**Shift+点击**从上次锚点扩展；单击已切片行仍是选中该切片（不残留行选区）；`Esc` 或点击表格外清除。右键菜单按选区自适应：全部未切片 →「✚ 用选中的表格行新增切片」；含已切片 →「⤵ 合并所选 N 个切片」（对应切片在原文里连续时）与「✕ 删除所选 N 个切片」（逐个删除，`Ctrl+Z` 可逐条撤销）。这样拖选不会再出现「原生蓝字 + 行高亮」两套选区叠加；要复制单元格文字可展开卡片里的「原始正文」或用「改」弹层。实测（山东自由裁量标准，942 行、行高 285/440px）：拖 3 行恰好 3 行、原生文字选区长度为 0；反向拖动、Shift 连选、Esc 清除、未切片行新增、删除所选 2 个切片（连按 2 次 `Ctrl+Z` 回到 836）全部通过（21 项真机断言）；
- **表格高亮不再串表、对齐率大幅提升（P2 已实现）**：对齐算法补了三处（见 [docs/05](docs/05-alignment.md#51-三项改进2026-11-04)）——①**整表单行复用**：整张表压成一行的 HTML（哪怕只有 1,000–2,000 字符）被第一行命中后不再把游标推过整行，后续行继续在同一行匹配；②**表题锚定**：两张表前几行内容相同（真实语料里的表C.1 / 表C.2）时，用 `table_label` 在候选区找自己的表题行，以「表题后 ~ 下一条表题前」为窗口整表重匹配，全部行命中才采纳，span 从表题行开始，切片的原文高亮不再跨两张表；③**相似度兜底**：源文 `m<sup>2</sup>` 清洗成 `200m2`、chunk 正文是 `200m` 这类上下标差异，精确/子串失配后按 `difflib` 在 600 行窗口内找 `ratio ≥ 0.93` 的最佳行。实测：全量 13 764 块对齐 **13 671（99.32%）**；本地包 DB37T 2464 **104/104**、DB37T 2972 **185/185**（原 99/104、160/185），山东本地包 756/757，FAC-RAG 97 份从 96.3% 提到 **99.28%**；2972 的 `-0142`（表C.2 第1-10行）span 从 [725,731] 修正为 [728,731]，原文只染表C.2（浏览器实测：该块 10 行高亮、表C.1 0 行）；
- **整表块 / 被切块器标成段落的表格也能高亮（P2 已实现）**：有的表格切片 `law_num` 只有表号没有「第X-Y行」（如「附 录 B 表B.1」），有的整张表被切块器压成了一个 `paragraph` 块（如 2972 的表A.7）。前者以前点卡片一行都不亮、后者卡片显示成段落让人以为丢表。现在：①`annotateTableRows()` 对没有行区间的块做「整表覆盖」兜底——把同表格块里还没被其它切片认领的行整表算给它，点卡片整表着色（倒序认领，排在后面的「注X」小块先拿剩余尾行，不会整表抢走）；②卡片头对「原文是 `<table>`、但 `chunk_kind` 不是 table/appendix」的块加琥珀徽章「表格·切块器标为段落」，title 说明是上游分类、可点「✎ 改」把类型改成 `table`。实测（2972）：`#125`（`-0120`，表A.7，paragraph）点选后第 697 行整表 6 行全高亮、其他表格块 0 行；`#128`（`-0123`，表B.1，无行区间）点选后第 711 行 6 行全高亮；无 pageerror；
- **从切片开头选中 → 扩展该切片（P2 已实现，文字 / 表格行都支持）**：在原文里从某个切片的**第一行行首**开始拖选、一直拖过这个切片的最后一行，再点「＋ 新增」/右键「选区新增」，弹层会切成「⤢ 扩展切片」：标题/说明/按钮都改成「扩展」，正文与条号预填成扩展后的结果，提交后是**在原切片上扩展**（把越过中间被覆盖的块并进来，不新增一块），`Ctrl+Z` 一次撤销。表格同理：在表格里从某个行区间切片的第一行选到最后一行以外，右键会显示「用选区扩展 #N 切片」；扩展后 `law_num` 行区间自动更新（如 `工作表格 表A.4 第1-2行` → `第1-5行`），正文按原文行/表格行重建。后端用原子操作 `extend`（校验连续、合并正文、保留目标 id、重排 id），编辑边界一律以「行」为单位（文本=源文件行，表格=`tr` 行）；
- **自动分 part（P2 已实现，设置里可开；P3 起为「真实块」）**：设置面板勾选「自动分 part」并给 `max_chars`（默认 800）/`min_part_chars`（默认 200）。开启后**编辑过程中**（加载、合并、扩展、新增、改正文）一产生超长块就立刻物化成真实 `-p1..-pN` 块——文本块按行装箱均分（每段重复面包屑、尾段不足 200 字符时与上一段重排、单行超长才在 `。；，` 处硬切），表格块只做「多行超长 → 按行区间拆成独立表格块」（`law_num` 写 `表X 第a-b行`；单行大表保持整块，不做列组 part、不做列内硬切）。part 是真实块：可以直接选中、删除、合并、改正文，撤销重放结果一致；前端用视图字段 `part_index/part_total` 显示「part 2/4」，用 `part_span` 画它真正覆盖的行段。删除某个 part 后同组剩余 part 自动重排编号（只剩一个时变回普通块）；
- **多选删除 / 分片删除确认（P3）**：卡片 `Ctrl`/`⌘` 多选后按 `Delete` 一次删除所选（原子 `drop_many`，一次 `Ctrl+Z` 撤销）；原文跨块拖选后右键也有「✕ 删除所选 N 个切片」。删除分片 part 时弹三选一——「只删这一片 / 删除整组 / 取消」；若选区里同一组 part 没选全，弹层提示「只删选中的 / 连同整组一起删 / 取消」；普通整块删除不弹确认。
- **双层泳道（P3）**：分片 part 在左栏画两根条——外层浅色 = 父块整段（组内 `part_span` 并集），内层深蓝 = 这一片真正覆盖的行段；卡片徽章写「part 2/4 · 第 a–b 行」，悬停任一条都能看父段与本片段落。
- 手改过的正文标 `manual` 徽章、`align = manual`，派生字段（`token_len` / `chunk_hash`）自动重算；
- **P3 落盘：草稿 → 提交（已实现）**：编辑只在内存进行，**自动保存草稿**（2 秒防抖、`Ctrl+S` 立即保存、切换文件时自动补存）写到 `data/draft/<名>.<基线sha12>.chunks.jsonl`；顶栏徽章显示「● 有未保存修改 / 草稿已保存未提交 / ⚠ 草稿已过期」，左栏文件行显示「草稿」标记。点「**提交**」时校验基线（正式 chunks 的 sha12 必须等于草稿文件名里的基线），一致才把旧版备份到 `data/backup/<名>.<时间戳>.jsonl`（保留最近 3 份）→ 原子替换 `data/chunks/<名>/<名>.chunks.jsonl`（只写 15 个契约字段，`token_len`/`chunk_hash` 重算、id 按位置重排）→ 删除草稿；「**放弃**」删草稿回到基线，「**导出**」下载当前块（含未提交修改）的 jsonl。草稿跟着**文件**走：切到别的文件、刷新页面、重启服务后再打开都能恢复；同一文件若基线已被外部改动，旧草稿会被忽略并提示过期；
- 快捷键：`Ctrl+Z` 撤销、`Ctrl+Y / Ctrl+Shift+Z` 重做、`Ctrl+Shift+N` 新增、`Ctrl+Enter` 拆当前块、`Delete` 删当前块、`Ctrl+K` 搜索、`Esc` 关弹层；
- P2 的编辑只在内存（按文件隔离、按会话隔离），刷新页面回到基线；**P3 起可保存草稿并提交落盘**（见上一条）。

## 它解决什么问题

FAC-RAG 的切块器已经能把 97 份法规/国标 Markdown 切成约 1.27 万块，并带完整元数据与质检，
但切得对不对只能靠翻 JSONL 或跑评测：**看不到原文，也改不了边界**。

SplitChunkAssistant 把「自动切块」变成「可人工复核与修正的切块」：

- 左：文件树（97 个文件、分组、块数、编辑状态、对齐徽章）
- 中：原文 Markdown 源码行（行号 + 切片高亮 + 节导航）
- 右：切片卡片（15 字段 + extras + 对齐状态 + 操作按钮）
- 顶部：参数面板（重切）、diff 计数、保存/重置/导出、gate 质检

## 不可动摇的约束

| # | 约束 | 说明 |
|---|---|---|
| 1 | **只处理 Markdown** | 原件是 97 份 `.md`，不引入 Docling / PDF / OCR / torch |
| 2 | **FAC-RAG 只读** | 不改它的代码、不写它的 `data/chunks_v2`、不写源 md |
| 3 | **契约不变** | 输出仍是 15 字段 + extras 侧车；`token_len` / `chunk_hash` 为派生字段 |
| 4 | **覆盖层存储** | 人工修改写 `edits/`，随时可回基线、可审计 |
| 5 | **零第三方依赖** | 后端 Python `http.server`，前端 vanilla JS，双击即可跑 |
| 6 | **本地单机** | 只监听 `127.0.0.1`，无账号、无网络请求 |
| 7 | **对齐如实标注** | `exact / table_rows / approx / miss`，定位不到不假装高亮 |
| 8 | **不接 RAGFlow** | 本期不引入任何知识库平台（理由见 [docs/07-decisions.md](docs/07-decisions.md)） |
| 9 | **先提案后动手** | 任何改文件/提交推送前，先说明方案并等用户确认（见 ADR D17） |

## 协作约定（2026-11-03 起）

改动流程固定为「提案 → 确认 → 动手 → 验证 → 汇报」，细则见 [docs/07-decisions.md](docs/07-decisions.md) 的 D17：

1. **只读排查直接做**：读代码、查数据、grep 不改文件，可直接进行。

启动脚本说明（2026-11-03 修复）：

- `run_studio.cmd` 是 **纯 ASCII + CRLF** 的批处理文件。此前版本是 UTF-8 + LF，cmd.exe 按 OEM 代码页读会把中文注释行拆坏、报「'默认端口' 不是内部或外部命令」，现已重写；

- 左侧法规文件（分组 / 搜索 / 块数，点击打开三栏）；
- 中间是原文 `.md` 的源码行（行号 gutter、标题/引用/表格/超长行折叠）；
- 右侧是切片卡片（15 字段摘要 + extras + 对齐状态），顶部显示 `对齐 N/N (率) · 各档计数`；
- hover 卡片 → 原文行淡高亮；hover 原文行 → 关联卡片标记；click 卡片 → 滚动并强高亮对应原文行；
- 地址栏形如 `#doc=national_laws%2F中华人民共和国消防法`，可直接收藏/分享定位；
- 卡片底部有 `拆 / 并↑ / 并↓ / 删 / 改` 操作；弹层里填拆分位置 / 改正文与条号 / 新增正文；

- 原文里拖选一段文字后点「＋新增」：弹层自动带入选区文本并记录行区间，提交后新块出现在原文对应行旁（范围条同步）；
- **左栏批量 / 拖拽导入原文件（P3 已实现）**：左栏搜索框下的「⬆ 添加文件」可一次选多个 `.md / .markdown / .txt`，或把文件直接拖到左栏（拖入时侧栏高亮 + 「松开导入到 data/source」提示）；浏览器读文件转 base64 提交 `POST /api/upload`，服务端校验文件名（禁路径穿越/控制字符）、只收 UTF-8（`.markdown`/`.txt` 统一存成 `.md`）、**同名不覆盖只跳过**、单文件 ≤16MB、整批 ≤64MB，写盘用临时文件 + 原子替换；写完后自动触发切块（chip 显示「切块中 n/m · 文件名」），切完左栏自动出现该文档；
- 顶部 `+a ~m -r` 是相对基线的 diff，`未保存` 徽章表示有内存编辑，撤销/重做可逐步回退；
- 「⚙ 设置」可改 `data_root` / 端口 / 自动分 part 三项 / 自动切块三项，保存即生效。

## 唯一数据源：本地「两目录」（data/source + data/chunks）

工作台只读本地两目录（2026-11-04 起移除 FAC-RAG `_manifest.json` 清单模式；2026-11-05 起每个文档的切片放进独立文件夹）：

```
data/
├── source/                      ← 原文件 .md，可带子目录（子目录名进分组）
│   └── 2025版山东省自由裁量标准.md
├── chunks/                      ← 切片：每个文档一个文件夹
│   └── 2025版山东省自由裁量标准/
│       ├── <名>.chunks.jsonl    ← 必需（15 字段；缺 token_len 会现算）
│       ├── <名>.extras.jsonl    ← 可选（每行平铺或 {"id","extras"} 嵌套）
│       └── <名>.report.json     ← 可选（切块引擎报告，带 gate）
├── draft/                       ← 未提交的草稿（自动保存；gitignore）
└── backup/                      ← 提交前的旧版备份（保留最近 3 份；gitignore）
```

- 加新文档最省事的方式：只把 `.md` 丢进 `source/`——自动切块引擎会生成 `chunks/<名>/` 三件套；已有切块包则手工建 `chunks/<名>/` 放 `<名>.chunks.jsonl`（+ 可选 `<名>.extras.jsonl`/`<名>.report.json`），再点顶部「**刷新**」（`POST /api/reload`），不用重启服务；`source/` 与 `chunks/` 的子目录名会成为分组名。
- 配对靠「同名 + 同相对路径」；`chunks/<名>/<名>.chunks.jsonl` 决定文件是否出现，`source/` 只作对照——缺源文件时文件仍列出，但打开会提示「源文件缺失」。
- `.extras.jsonl` 两种写法都支持：字段平铺（切块包风格）或 `{"id": …, "extras": {…}}` 嵌套（FAC-RAG 风格）。
- 本地源没有 gate/sha256 等质检信息，界面对应位置显示「—」；对齐、编辑、表格视图、行选择全部照常可用。
- 设置面板（⚙ 设置）里可改 `data_root`、端口、自动分 part 三项、自动切块三项；`data_root` 必填（默认 `data/`，已 gitignore）。

## 自动切块（SPLITCHUNK 引擎）

`data/source/` 里出现新 `.md`、而 `chunks/` 里还没有同名切片时，工作台会自动调用切块引擎生成切片，再刷新左栏：

- 引擎是上游 `chunking_v2`（0.1.4）的副本，放在 `vendor/splitchunk/`（随仓库提交，`vendor/splitchunk/UPSTREAM.md` 记录来源与 sha256、许可提醒）；设置里「切块引擎目录」留空即自动探测（`vendor/splitchunk`，找不到回退 `../SPLITCHUNK`）。
- 工作台**不把引擎装进自己的进程**：每份文件起一次 `python -m chunking_v2.cli …--json` 子进程，产物先写临时目录 `data/.tmp_chunk/<名>/`，再原子发布到 `chunks/<名>/`（`<名>.chunks.jsonl / <名>.extras.jsonl / <名>.report.json`）；子进程挂了只记录失败，不影响工作台。
- 轮询间隔默认 3 秒（设置可改 1–60），mtime 小于 1.5 秒的文件先跳过（防半文件）；同一时刻只有一个切块任务。
- `<名>.report.json` 里带 gate 结果，左栏文件行相应显示 ✓ / ⚠；源文件改过（sha256 变化）时被列为「过期」，默认不自动重切，避免重排 id 影响手改叠加层——需要重切就手动触发。
- 手动：顶部「⚙ 切块」扫描待切文件并异步切块；工具栏左侧 chip 显示「切块中 n/m」「待切块 N 份」或上一次结果（8 秒）。
- 设置项：`auto_chunk`（默认开）、`chunker_root`（留空自动）、`chunker_poll`（秒）、`chunker_strategy`（`auto`/`profile`）。

- `/api/files` 以本地 `data/` 为准（示例环境 **9 个文件 / 1 941 块**：山东自由裁量 754、2464 104、2972 185、安全生产法 129，其余为后加入的法规），`mode=dirs`、单组 `data`
- 实测：`data/2025版山东省自由裁量标准` 757 块 / 606 行，对齐 **756/757（99.87%）**；`/api/tables` 返回 687 张表（首表 headers `编号|违法行为|法律规定|处罚依据|裁量阶次|适用条件|处罚标准`）

- `/api/tables?key=…` 返回该文件所有表块的 `table_grid`（`chunk_id → {headers, rows, width, header_rows, note_from, table_label, table_title, table_mode, table_rows}`，最近 8 个文件缓存）；用于右栏表格可视化，缺 key 400、未知 key 404

- P2 编辑：`POST /api/op`（split / merge / drop / add / patch）、`/api/undo`、`/api/redo`、`/api/reset`；
  `add` 可带 `span:[起始行,结束行]`（原文选区新增，1-based 闭区间）；插入位置用 `after_id`（之后）或 `before_id`（之前），都不传则追加到末尾；
  新增后按原文位置重排 id（新块拿它在列表里的序号，插入点之后的块顺延；多 part 组继续共用 base 序号），diff 用内容 LCS 配对，插入只报 `+1 ~0 -0`；
  拆分后块数 +1、diff 同步（拆分暂不重排 id，保持原有 id 语义）
- P3 落盘：`POST /api/draft/save`（写 `data/draft/<名>.<基线sha12>.chunks.jsonl`）、`POST /api/draft/discard`、`POST /api/draft/commit`（校验基线 → 备份到 `data/backup/` 保留 3 份 → 原子替换 `chunks/<名>/<名>.chunks.jsonl`，只写 15 字段 → 删草稿）、`GET /api/export?key=…`（下载当前块 jsonl）；`/api/doc` 返回 `draft:{exists,stale,baseline12,saved_at}`，`/api/files` 每个文件带 `draft`/`draft_stale`
- 静态页 `/`、`/static/app.js`、`/static/style.css` 均可直出
